# Deploy รอบใหม่ — ข้อสอบส่วนที่ 2 (Word 15 / Excel 25) + รายงานกรรมการ

อัปเดตนี้เปลี่ยน 4 อย่าง: โจทย์ส่วนที่ 2, วิธีตรวจและการให้คะแนน, ไฟล์รายงานผลตรวจใน Drive, และรายงาน PDF สำหรับกรรมการ
ทำตามลำดับ 1 → 4 แล้วรันชุดทดสอบข้อ 5

## 1. อัปเดต Supabase (SQL)

เปิดแอป → แท็บ **ตั้งค่ารอบสอบ** → ปุ่ม **ดาวน์โหลด SQL** → เปิดไฟล์ → วางใน Supabase → SQL Editor → Run
รันซ้ำได้ปลอดภัย (`create if not exists` / `add column if not exists` / `create or replace`)

สิ่งที่เพิ่มในรอบนี้:

| สิ่งที่เพิ่ม | ใช้ทำอะไร |
| --- | --- |
| `dl_sessions.part2_grading jsonb` | เก็บคะแนนแยก Word/Excel, คะแนน AI ก่อนแอดมินแก้, สถานะ `COMPLETED / MANUAL_REVIEW_REQUIRED`, รายการเกณฑ์ที่ต้องตรวจซ้ำ, rubric version |
| `dl_sessions.admin_reason text` | เหตุผล / บันทึกกรรมการ ที่กรอกตอนบันทึกผล (แสดงในรายงาน PDF) |
| `dl_attitude_bank` | คลังคำถามวัดทัศนคติ (หมวดคำถาม · คำถาม) — สร้างไว้ก่อน ยังไม่ใช้ในการสอบ |
| ฟังก์ชัน `dl_save_session` | เขียน 2 คอลัมน์ใหม่ (ต้อง Run ทับของเดิม ไม่ต้องลบ) |

ตรวจหลังรัน:

```sql
select column_name from information_schema.columns
where table_name = 'dl_sessions' and column_name in ('part2_grading','admin_reason');
-- ต้องได้ 2 แถว

select count(*) from public.dl_attitude_bank;  -- ต้องรันได้ ไม่ error
```

> คะแนนที่ AI ตรวจถูกเก็บไว้ใน `part2_grading.ai_score` เสมอ ถ้าแอดมินแก้คะแนน คะแนนใหม่จะอยู่ที่คอลัมน์ `part2` และเหตุผลอยู่ใน `admin_reason` + `part2_edits` — คะแนน AI เดิมไม่ถูกเขียนทับ

## 2. อัปเดต Apps Script (ตัวตรวจไฟล์จริง)

1. เปิด script.google.com → โปรเจกต์ DL → วางไฟล์ `Code.gs` ตัวใหม่ทับทั้งไฟล์
2. แก้ 3 ค่าบนหัวไฟล์: `ROOT` (โฟลเดอร์แม่), `HR_EMAIL`, `SHARED_SECRET` (ต้องตรงกับช่อง Secret key ในแท็บตั้งค่าของเว็บ)
3. **Services → เพิ่ม Drive API** (ต้องมี ใช้แปลงไฟล์เป็นสำเนาสำหรับตรวจ)
4. Deploy → **Manage deployments → Edit → New version → Deploy** (ถ้าสร้าง deployment ใหม่ URL จะเปลี่ยน ต้องนำไปวางในเว็บอีกครั้ง)
   - Execute as: **Me** · Who has access: **Anyone**
5. รัน `testPing()` ครั้งแรกเพื่ออนุญาตสิทธิ์ Drive/Docs/Sheets
6. กลับมาที่เว็บ → แท็บตั้งค่า → วาง Web App URL + Secret key → กด **ทดสอบการเชื่อมต่อ**

หลักการที่สคริปต์ยึด (ตาม AI Grader Prompt v1):

- ไฟล์ที่ผู้สมัครส่งเป็น **ต้นฉบับ ห้ามแก้** — ระบบสร้างสำเนา Google Docs/Sheets เพื่ออ่านค่า แล้วลบสำเนาทิ้งหลังตรวจ
- ให้คะแนนจากหลักฐานที่วัดได้เท่านั้น ทุกเกณฑ์คืนค่า Expected / Actual / Evidence / Status / Reason / Confidence
- นับจำนวนหน้าเอกสารด้วยการ export PDF ชั่วคราว ถ้านับไม่ได้ → `MANUAL_REVIEW` และ **ไม่หักคะแนนอัตโนมัติ**
- ค้นคอลัมน์ Excel จากหัวตาราง ไม่ยึดตำแหน่ง G/H และรับสูตรที่เทียบเท่ากัน (`D2*E2`, `PRODUCT(D2,E2)`, `IF(F2<>G2,...)`)

## 3. เกณฑ์การให้คะแนนส่วนที่ 2 (40 คะแนน)

| เกณฑ์ | คะแนน | ตรวจอะไรจริง |
| --- | --- | --- |
| W1 ข้อมูลครบ 10 รายการ | 4 | ชื่อประชุม/วัน/เวลา/สถานที่/ผู้เข้าร่วม/ผู้ประสานงาน/วาระ 1-4 · 10 ครบ=4, 8-9=3, 6-7=2, 4-5=1 |
| W2 รูปแบบชื่อการประชุม | 3 | ข้อความถูก 1 · 18 pt 0.5 · Bold 0.5 · Center 1 |
| W3 ฟอนต์เนื้อหา | 2 | TH Sarabun New ≥90% = 1 · ขนาด 16 pt ≥90% = 1 (60-89% ได้ครึ่ง) |
| W4 Numbering อัตโนมัติ | 2 | list item แบบมีเลขครบ 4 = 2 · บางส่วน = 1 · พิมพ์เลขเอง = 0 |
| W5 ตัวหนา วัน/เวลา/สถานที่ | 2 | ครบ 3 = 2 · 2 = 1.5 · 1 = 0.5 |
| W6 ความยาว + ชื่อไฟล์ | 2 | ไม่เกิน 1 หน้า 1 · ชื่อไฟล์ `เชิญประชุม_<รหัส>.docx` 1 |
| E1 ข้อมูลต้นฉบับ A–F | 2 | เทียบจำนวน/ราคา/ยอดขอเบิก 6 รายการ · ผิด 1 จุด = 1 |
| E2 ยอดคำนวณ | 6 | รายการละ 1: สูตร+อ้างอิง+ผลถูก = 1 · สูตรผลถูกแต่อ้างอิงไม่ตรง = 0.75 · มีสูตรผลผิด = 0.5 · พิมพ์เลขเอง = 0.25 |
| E3 สถานะตรวจสอบ | 6 | รายการละ 1: IF + ข้อความถูก = 1 · มี IF ผลผิด = 0.5 · ข้อความถูกแต่ไม่มีสูตร = 0.25 |
| E4 SUM = 28,425 | 3 | SUM ถูก = 3 · สูตรรวมแบบอื่นผลถูก = 2 (Strict SUM) · พิมพ์เอง = 0.5 |
| E5 Conditional Formatting > 5,000 | 4 | threshold ถูก + ช่วงคลุมยอดคำนวณ = 4 · ช่วงไม่ครบ = 3 · threshold ผิด = 1 · ใส่สีมือ = 0.5 |

| E7 ชื่อไฟล์ + โครงสร้าง | 2 | `ค่าใช้จ่าย_<รหัส>.xlsx` 1 · เปิดได้และหัวตารางครบ 1 |

## 4. ไฟล์ที่ระบบสร้างให้อัตโนมัติ

| ไฟล์ | ที่อยู่ | สร้างเมื่อ |
| --- | --- | --- |
| `เชิญประชุม_<รหัส>.docx`, `ค่าใช้จ่าย_<รหัส>.xlsx` | `/DL_2569/<ชื่อ>_<รหัส>/` | ผู้สมัครอัปโหลด (เก็บเป็นต้นฉบับ) |
| `รายงานผลตรวจ_<ชื่อ>_ส่วนที่2.docx` | โฟลเดอร์เดียวกัน | หลังระบบตรวจเสร็จ — มี Expected/Actual/Evidence/Reason/Confidence ทุกเกณฑ์ + รายการ MANUAL_REVIEW |
| `รายงานกรรมการ_<รหัส>.doc` | ดาวน์โหลดจากหน้าแอดมิน | กดปุ่มในหน้ารายงาน |

## 5. ชุดทดสอบก่อนใช้จริง

### 5.1 การรับไฟล์
- [ ] อัปโหลดชื่อไฟล์ผิด (`เชิญประชุม.docx`) → ระบบเตือนให้ใส่รหัสผู้เข้าสอบ และยังไม่ RECEIVED
- [ ] อัปโหลดครบ 2 ไฟล์ชื่อถูก → ขึ้น RECEIVED และเริ่มตรวจทันที
- [ ] เปิด Drive → ไฟล์ต้นฉบับอยู่ในโฟลเดอร์ผู้สมัคร และไม่มีสำเนา `_grading` ค้าง

### 5.2 การตรวจและคะแนน
- [ ] ทำไฟล์ให้ถูกทุกข้อ → ได้ 40/40 และไม่มี MANUAL_REVIEW
- [ ] แก้ threshold Conditional Formatting เป็น 3,000 → E5 ได้ 1/4 และ Evidence ระบุ threshold ที่พบ
- [ ] พิมพ์ตัวเลขยอดคำนวณเองแทนสูตร → E2 ได้ 0.25/รายการ
- [ ] พิมพ์เลข 1. 2. 3. 4. เองใน Word → W4 ได้ 0/2
- [ ] ทำเอกสาร 2 หน้า → W6 หักครึ่ง (1/2)

### 5.3 ไฟล์รายงานผลตรวจ
- [ ] มีไฟล์ `รายงานผลตรวจ_...docx` ในโฟลเดอร์ และเปิดอ่านได้
- [ ] ในไฟล์มีทุกเกณฑ์ W1–E7 พร้อม Evidence ที่อ้างเซลล์/ย่อหน้าจริง

### 5.4 รายงานกรรมการ
- [ ] กรอก "เหตุผล / บันทึกกรรมการ" แล้วกดบันทึกผล → เปิดรายงาน PDF เห็นข้อความนั้นในกล่อง "บันทึกกรรมการ"
- [ ] คำถามสัมภาษณ์มา 3 ข้อ ข้อละส่วน และผูกกับเกณฑ์ที่คะแนนต่ำสุดจริง
- [ ] กด "ดาวน์โหลด PDF" → พิมพ์ได้ 1 หน้า ไม่มีเมนู/ปุ่มติดไปในไฟล์
- [ ] กด "ดาวน์โหลดไฟล์รายงาน (.doc)" → เปิดใน Word/Google Docs ได้

### 5.5 ของเดิมที่ต้องไม่พัง
- [ ] นาฬิกาทั้ง 3 ส่วนเลื่อนตามหน้าจอ ไม่ถูกแถบหัวเว็บทับ
- [ ] หมดเวลาแต่ละส่วน → Alert บังคับกดไปส่วนถัดไป (ส่วนที่ 2 ได้เวลาเพิ่ม 10 วินาที)
- [ ] รายการที่บันทึกผลแล้ว แก้/ลบ/รีเซ็ตไม่ได้ในระบบ
- [ ] แอดมินรีเซ็ตรายส่วนได้ และเวลาส่วนที่รีเซ็ตเริ่มนับใหม่
