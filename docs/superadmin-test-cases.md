# Test Cases · Superadmin Security Gate

`ผ่าน` = ทดสอบได้ในระบบนี้ · `ต้องทดสอบบน Supabase จริง` = ต้องมีโปรเจกต์ที่รัน SQL + เปิด MFA แล้ว

## สิทธิ์

| # | กรณี | ผลที่ต้องได้ | สถานะ |
|---|---|---|---|
| 1.1 | ผู้ใช้ทั่วไปเรียก REST endpoint ของผลสอบตรง | ถูก RLS ปฏิเสธ | ต้องทดสอบบน Supabase จริง |
| 1.2 | Admin เปิด Dashboard และบันทึกผลคะแนน | ทำได้ | ผ่าน |
| 1.3 | Admin กดบันทึกการเชื่อมต่อ | เปิด Gate และ server ปฏิเสธเมื่อไม่มี `integration.manage` | ต้องทดสอบบน Supabase จริง |
| 1.4 | Superadmin ที่ยังไม่ผ่าน MFA แก้ค่าระบบ | ถูกปฏิเสธด้วย `mfa_required` | ต้องทดสอบบน Supabase จริง |
| 1.5 | Superadmin ผ่าน MFA `aal2` | ดำเนินคำสั่งได้ และมีแถวใน audit log | ต้องทดสอบบน Supabase จริง |
| 1.6 | Superadmin แต่งตั้ง Superadmin คนอื่น | `dl_set_role` ปฏิเสธ (ไม่มี `role.manage`) | ต้องทดสอบบน Supabase จริง |
| 1.7 | ผู้ใช้เปลี่ยน role ของตัวเอง | `self_role_change_not_allowed` | ต้องทดสอบบน Supabase จริง |
